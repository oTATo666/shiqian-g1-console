# 时迁主控台 1.1.0 · 使用说明

> 本目录是「时迁主控台 1.1.0」的**可运行代码**，由 `时迁主控台UI完整开发文档与源码_1.1.0.docx` 中的源码原样落地，并做了最小精修。开发文档与源码清单仍以那份 docx 为准。

## 一、目录

```
时迁主控台_1.1.0/
├─ 启动时迁主控台.bat     唯一启动入口（Windows）
├─ console_ui.py          Flask 后端：API 路由 + 子进程管理
├─ requirements.txt       flask / pyyaml / requests
├─ codes.csv              核销码池（code,status,time）
├─ config.yaml            运行配置（不含任何密钥，见第十一节）
├─ templates/console.html 单页主控台（六大视图）
├─ static/tailwind.css    编译好的样式（本地文件，**不依赖外网 CDN**）
├─ static/style.css       自定义滚动条与等宽终端样式
├─ static/app.js          轮询、状态机、配置读写、Toast
├─ static/shiqian.png     时迁的虚拟形象（侧栏头像 / 标签页图标）
└─ 使用说明.md            本文件
```

> 样式是本地编译的静态 CSS（约 19 KB，只包含实际用到的类）。
> 早期版本用 `<script src="https://cdn.tailwindcss.com">` 在浏览器端现算样式，
> 一旦断网或访问不到该域名，整页会退化成无样式的纯文本 —— 现在不会再出现这种情况。
> 改完 `console.html` 若要重新生成样式，见文末「九、样式本地化与重新编译」。

## 二、三步跑起来

```bat
:: 1) 首次装依赖（或双击启动脚本，它会自动装）
python -m pip install -r requirements.txt

:: 2) 启动（二选一）
启动时迁主控台.bat
python console_ui.py

:: 3) 浏览器打开
http://127.0.0.1:5000
```

`config.yaml` 不存在时会自动生成一份默认配置；以后在网页「系统设置」里改，保存时自动备份为 `config.yaml.bak`，可点「回滚上次配置」。

> **密钥不在这个文件里。** API Key、核销口令都不写 `config.yaml`，而是存进系统凭据库；页面上只显示 `********`。详见第十一节。

## 三、后端模块：直接复用现成工程的代码

主控台通过子进程调用**现有「时迁」工程**里的模块，不复制、不修改那些源码：

| 页面模块 | 调用的文件 |
| :--- | :--- |
| 语音交互 (asr) | `main.py` |
| 核销后台服务 (redeem) | `web_redeem_server.py` |
| 离线替身机器人 (mock) | `mock_robot_server.py`（「离线演示」开关触发） |
| 动作分发中心 (action) | `action_dispatcher.py`（若工程未提供独立入口，会跳过并记日志） |
| 机器人传感 (sensor) | `sensor_bridge.py`（**必须用 conda g1 的 Python 3.10 跑**，见第十三节） |

默认后端目录是同级 `../shiqian_v9`。换位置就设环境变量：

```bat
set SHIQIAN_BACKEND_DIR=D:\path\to\your\时迁工程
```

找不到的模块会在「实时运行日志」里写明"跳过"，**不影响主控台本身运行**；页面状态矩阵会如实显示未运行。

1. 去除 Word 软换行还原时带入的 BOM（否则 CSV 首列读成 `\ufeffcode`，核销会失败）

6. 新增 `SHIQIAN_BACKEND_DIR`，让主控台能直接调用现成工程的代码文件
7. **样式本地化**：原来引用在线 Tailwind CDN，断网/被墙时整页无样式；改为本地编译的 `static/tailwind.css`

**未改动**：报告中的 UI 设计、六大视图、API 结构。配置字段有增删（删掉 3 个密钥字段、新增 3 个占位字段），见第十一节。

## 八、常见问题

- **端口被占用**：改 `config.yaml` 的 `server.consoleport`，或网页「系统设置」里改后重启。
- **页面显示"依赖未安装"**：点概览页的「一键安装依赖」，或手动装 `requirements.txt`。
- **点了"一键启动系统"没反应**：看「进程与日志」→ 多半是 `SHIQIAN_BACKEND_DIR` 没指到后端工程；主控台本身仍可正常做配置、码池核销。
- **中文乱码**：启动脚本已 `chcp 65001`；命令行手动启动时也先执行 `chcp 65001`。

## 九、样式本地化与重新编译

页面只引本地文件：`/static/tailwind.css`（编译好的样式）+ `/static/style.css`（自定义滚动条等）。**不再需要外网**，断网、内网、无 DNS 的教室机器都能正常显示。

改过 `console.html` 或 `app.js` 后，如果新增了没见过的 class，需要重新生成样式：

```bat
:: 一次性准备（只需一次）
npm i -D tailwindcss@3

:: 生成（在项目根目录执行）
npx tailwindcss -i ./tw-input.css -o ./static/tailwind.css --minify ^
  --content "./templates/console.html,./static/app.js"
```

`tw-input.css` 只有三行：

```css
@tailwind base;
@tailwind components;
@tailwind utilities;
```

产出约 19 KB，只包含页面实际用到的类。**判断有没有漏**：打开页面后看浏览器控制台，
若某个区块样式不对，多半是新加的 class 还没编译进去，重跑一次上面的命令即可。
也可以直接改 `static/style.css` 手写样式，它不受编译影响，优先级在 `tailwind.css` 之后。

## 十、子进程托管：启动判定、输出泵、文字投喂

这一节讲的是主控台怎么"管住"它拉起来的四个后端模块。

### 1. 启动失败会被当场指出，而不是只留一个 PID

`start_process()` 拉起进程后会在 **1.5 秒** 后回看一眼：

- 还活着 → 标记 `运行中`，把窗口内攒的输出补进日志；
- 已经退出 → 标记 `启动失败`，并把**它退出前吐出的全部内容整段贴进日志**，末尾再带一行排查建议。

没有任何输出就退出时，会额外提示常见原因（缺依赖 / 端口占用 / 脚本要交互输入）。

页面上体现为：概览的模块卡变红显示「启动失败」，进程页的 PID 行变成「已退出（退出码 ≠ 0）」。

### 2. 输出泵：必须有人一直读，否则子进程会卡死

`Popen` 的 stdout 是**管道**，管道缓冲区（Windows 约 64 KB）写满后，子进程下一次 `print` 就会阻塞 ——
表现是"启动了、也在跑，但永远没反应"。所以每个模块都有一个后台线程持续 `readline()`：

```
pump-asr / pump-action / pump-redeem / pump-mock
```

读到就追加进日志。日志是**环形缓冲**（`deque(maxlen=500)`），只保留最近 500 行，
跑一整天也不会把内存吃满。

### 3. 托管模式：不再假装能读键盘

被主控台拉起时，子进程的 `stdin` 指向 `DEVNULL` —— 那里没有终端，`input()` 只会立刻读到 EOF。
所以 `main.py` 启动时会判断一次：

```python
headless = (not args.keyboard) and (args.headless or not stdin_is_tty())
```

进入托管模式后：

- 跳过 `input()` 循环，改为在 `127.0.0.1:5010` 开一个小 HTTP 口；
- 主循环用 `queue.get(timeout=0.5)` 等待，**不阻塞、不会因 EOF 退出**；
- 收到文本后照常走：提炼记忆点 → 下发动作 → 出票 → 播报。

接口只有两个：

```http
POST /input    {"text": "我想和室友一起拍张照"}
GET  /health   -> {"ok": true, "mode": "headless", "queued": 0}
```

端口在 `config.yaml` 的 `worker.port` 里改（默认 5010），主控台会用环境变量把它传给子进程，两边不会错位。

### 4. 在页面上投喂

「实时操控」页新增「文字投喂（托管模式）」面板：输入框 + 投喂按钮，回车也能发；
下面三个快捷句子方便演示。右上角会显示当前状态：`已就绪 · PID 1234` / `正在启动…` / `语音主程序启动失败`。

它等价于原来"对着黑窗口打字"，但走的是 HTTP，子进程在哪个终端里都无所谓。

**注意**：日志里只记录"投喂了多少字"，不记录内容本身（总原则第 4 条）。

```bat

:: 或者直接问托管中的主程序还活着没
```

## 十一、密钥与配置项

### 1. 密钥不再写进 config.yaml

原来 `g1.apikey`（机器人接口）、`llm.apikey`（大模型）、`redeem.adminpassword`（核销口令）
是明文存在 `config.yaml` 里的，`GET /api/config` 还会原样返回。**现在两者都改了**：

| 字段 | 存在哪 | 对应环境变量（可选） |
| :--- | :--- | :--- |
| `g1` 的接口密钥 | 系统凭据库 | `SHIQIAN_G1_APIKEY` |
| `llm` 的 API Key | 系统凭据库 | `SHIQIAN_LLM_APIKEY` |
| 核销后台口令 | 系统凭据库 | `SHIQIAN_REDEEM_ADMINPASSWORD` |

**存放优先级**（自动选，不用配）：

1. `keyring` → Windows 凭据管理器（装了 `keyring` 就走这条，最推荐）
2. 没有 keyring 但系统是 Windows → **DPAPI** 加密到 `data/.secrets.dpapi`，密文只能用当前 Windows 账户解开
3. 两者都没有（非 Windows 且无 keyring）→ 只认环境变量，页面上保存密钥会**明确拒绝**并提示，绝不退回写明文

**读取优先级**：环境变量 → 系统凭据库 → DPAPI 文件 → 老 `config.yaml` 里的遗留明文。

### 2. 页面上怎么填

「系统设置」里两个密码框的行为：

| 你看到 / 你做的 | 结果 |
| :--- | :--- |
| 显示 `********` | 说明已配置过，**这是掩码，不是你的密码** |
| 不动它直接保存 | 保留原值，不会被掩码覆盖 |
| 删空后保存 | 真的删除该密钥 |
| 填新值保存 | 覆盖旧的；只写凭据库，`config.yaml` 里搜不到 |

`GET /api/config` 返回的 `secrets` 字段可以看"配没配"，但它只给布尔值：

```json
"secrets": {"backend": "keyring", "configured": {"g1.apikey": true, "llm.apikey": false, "redeem.adminpassword": false}}
```

> 掩码固定 8 个星号，**不反映真实长度**。界面上看不到、也导不出真值。

### 3. 老配置会自动迁移

如果你手上有一份旧 `config.yaml`（里面还写着明文密钥），第一次启动/第一次读配置时会：

1. 把三个值搬进凭据库；
2. 把文件里的密钥字段删掉并回写；
3. 在日志里记一行「已把 N 项明文密钥移入 keyring」。

迁移失败（比如没有 keyring 也没 DPAPI）时**不会丢密钥**：值只在内存里兜底，日志会提示文件里仍留着明文，需要你手动改环境变量。

### 4. 三个占位字段（**尚未实现，填了也不生效**）

```yaml
llm:
  proxy_url_env: ''      # 以后接代理/换供应商时，填"读哪个环境变量"的名字
skills:
  endpoint_env: ''       # 以后 skills 托管用
avatar:
  enabled: false         # 以后虚拟形象接入开关
```

代码里**没有任何地方读它们**，保持现状即可。

> 从「系统设置」页保存时，没在表单里的段（`skills` / `avatar` / `llm.proxy_url_env`）会被**原样保留**：
> 后端会把本次没提交的段从旧文件合并回来，只补缺、不覆盖你这次改的值。
> （早先版本会整段冲掉，已修。）

## 十二、便携版（给别人用，免安装）

给没有 Python 环境的电脑用，需要打「便携版」——在项目目录**外面**多一层：

```
时迁主控台_1.1.0_便携版\
├─ ①双击启动.bat        纯 ASCII 启动入口
├─ launcher.py          打印中文提示、开浏览器、拉起服务
├─ runtime\             内置 Python 3.14 + 全部依赖（约 106 MB）
├─ 时迁主控台_1.1.0\     本目录
├─ shiqian_v9\
└─ 00_先看这里.txt
```

### 1. 为什么启动器要拆成 bat + py

原来 `.bat` 里直接写中文，靠 `chcp 65001` 显示。问题是 UTF-8 批处理里的**全角标点**
在某些 Windows 上会被 cmd 当成命令分隔，导致某一行报
`'xxx' is not recognized as an internal or external command`。

现在 `.bat` 里**一个字中文都不写**，只负责找到解释器；所有中文提示由 `launcher.py` 打印。
两边的批处理都可用 `notepad` 打开核对，全程 ASCII。

### 2. 内置运行时怎么被选中的

`启动时迁主控台.bat` 的第一件事：

```bat
set "PY=..\runtime\python.exe"
if not exist "%PY%" set "PY=python"
```

有 `runtime` 就用它（目标机器装没装 Python 都不影响）；没有才退回系统 Python。
所以同一份代码，开发机上照样能跑。

### 3. 内置运行时是怎么做的（要复现的话）

1. 下 `python-3.14.0-embed-amd64.zip`（官方 embeddable 包，约 11 MB），解压到 `runtime\`
2. 改 `python314._pth`，加两行：`Lib\site-packages` 和 `import site`
3. 用同版本 Python 安装依赖到 `runtime\Lib\site-packages`：

```bat
python -m pip install --target runtime\Lib\site-packages ^
  flask pyyaml requests keyring pywin32-ctypes cryptography pillow pyserial ^
  fastapi uvicorn pydantic SpeechRecognition
```

依赖必须与内置解释器**同版本同架构**，否则带 `.pyd` 的包（PyYAML、cryptography）会加载失败。

### 4. 便携版里没有的东西

- 语音识别模型（Vosk）、`pyaudio`、`pygame`、`bleak` —— 体积大或有二进制依赖，未内置。
  没它们时语音会自动降级到键盘/文字，不影响核销与配置。
- 你的 API Key —— 存在当前 Windows 账户的凭据管理器里，不会跟着包走。
  换台机器要在「系统设置」重新填，或用环境变量。

## 十三、机器人传感页（G1 实机）

侧栏新增第 7 个视图「机器人传感」：把 G1 身上真正拿得到的传感器接到页面上。

### 1. 为什么单独一个进程

便携版内置的是 **Python 3.14**，而 G1 的 DDS（`unitree_sdk2py`）只装在 conda 的 `g1` 环境（Python 3.10 + cyclonedds 0.10.2 + numpy）。
所以结构是：

```
页面  →  主控台 (5000, Flask)  →  传感器桥 (5011, conda g1)  →  DDS / UDP 组播
```

主控台只做代理，**不需要**在主控台里装任何机器人依赖。

- 解释器自动探测顺序：`config.yaml → sensor.python` → 环境变量 `SHIQIAN_SENSOR_PYTHON` → `~/miniconda3/envs/*`、`C:/ProgramData/miniconda3/envs/*` 里能 `import unitree_sdk2py` 的那个。

### 3. 麦克风怎么开

页面上的「开始采集」= 调 voice 服务的 **API 1008**（`{"mode":1}`，麦克风推流 + ASR），
然后自己加入组播收 PCM。官方 Python SDK 没封装 1007/1008，桥里是裸 RPC 调的。

- 停止时会 **还原成打开前的 mode**，不会把机器人自带的语音助手一直关着。
- 录音缓冲上限 60 秒，停止后落盘 `shiqian_v9/data/mic_last.wav`，页面「下载 WAV」直接取。
- 注意：组播出来的是**已经合成好的单声道**，拿不到 4 个麦克风的原始通道。

### 4. 视频为什么可能没画面

2026-11-17 实测这台 G1：机载电脑（192.168.123.164）上 `lsusb` 只有 Realtek Hub，
**没有 Intel RealSense**；`/dev/video*` 不存在，`/sys/class/video4linux` 为空；

1. 头部相机排线（D435i 那根 USB）有没有插紧 / 头部有没有供电；

3. 有画面后页面会自动出图（桥订阅 `rt/frontvideostream`，JPEG 帧直接转 MJPEG 给浏览器）；
4. 如果拿到的是 H.264，浏览器不能直接放，页面会提示"需要机载推 MJPEG"。

> 也可以用外部视频源：`config.yaml → sensor.videourl` 填 MJPEG 地址（例如机载另起的推流），桥会自己去拉。

### 6. 顺手修掉的一个坑

本机如果挂着 Clash 之类的代理，`requests` 会把发往 `192.168.123.x` 的请求也塞进代理，
表现为"机器人明明在线，概览页却显示离线"。主控台现在对机器人/本机请求统一用一个
`trust_env = False` 的会话，不再受系统代理影响。

### 7. 自动切句（VAD）与机器人播报

**自动切句**：麦克风不再"手动按开始/结束录音"，打开一次就一直听，按静音自动断句。

- 每个 UDP 包 160ms 切成 8 个 20ms 帧，逐帧算 RMS；
- 底噪自适应（只在非人声时更新），阈值 = 底噪 × 3，另有 0.006 的绝对下限；
- 连续 3 帧超阈值算"开口"，连续 25 帧（500ms）低于阈值算"说完"；
- 每句保留开口前 200ms，短于 0.35s 的丢弃（咳嗽/碰麦），超过 12s 强制断开；
- 切出来的句子落盘 `shiqian_v9/data/segments/*.wav`，页面可逐条播放/下载，最多留 40 条。

现场太吵或太安静，改 `sensor_bridge.py` 顶部的 `VAD_THRESHOLD_RATIO` / `VAD_ABS_FLOOR`。

**机器人播报**：页面右下「机器人播报」直接调 voice 服务 API 1001，用 G1 头部喇叭念，
不经过电脑音箱，也不依赖 edge-tts（便携版本来也没装）。

**关于"只会说唤醒模式"**：voice 服务的 `set_mode(1)` 会让机器人播一段唤醒提示。
桥现在会先读当前 mode，**已经是 1 就不再发 set_mode**，避免每次点"开始监听"都重播一遍。

## 十四、动作模组（`.g1motion` 回放）

**它解决什么**：在 G1 的 BVH 管道里把动作映射好后，导出成一个文件，
拿到时迁主控台里直接回放，不用再装 Python/conda。

### 1. 文件从哪来
G1 管道界面（`pipeline_gui.bat`）→ 加载 BVH → 调好滤波/预设 →
点 **「💾 保存动作模组」**。保存时如果检测到本机的时迁动作库，会问一句
要不要顺手复制进去，选「是」就不用手动搬文件。

一个 `.g1motion` 就是 zip：`meta.json`（帧率、关节顺序、来源、备注）+ `joints.npy`（N×29，弧度）。
单文件自带全部信息，换电脑、换目录都不影响。

### 2. 怎么导入
「动作模组」页 → 把文件拖进虚线框，或点「选择文件」。
也支持 `.npy`（按 100Hz 解读）和管道导出的 `.csv`（按首列时间算帧率）。
导入时会自动：检查 29 关节 → 裁剪到官方 URDF 限位 → 落盘到 `时迁主控台_1.1.0/motions/`。

### 3. 怎么回放
1. 动作库里点一行（右侧出现关节曲线，5 条：左髋/左膝/右髋/右膝/腰转）
2. 选 **回放模式**：
   - `上半身 arm_sdk`（默认）：内部平衡控制器继续跑，只接管 腰+双臂 12~28 关节，**最安全**
   - `低层全关节`：会先释放内置运动模式再接管 29 关节，**没吊架会摔**
3. 选 **回放速度**：0.1x / 0.2x（首测推荐）/ 0.25x / 0.5x / 1x
   0.2x 表示 18 秒的动作机器人用 90 秒走完
4. 点「▶ 回放到机器人」，右上角状态点会从「空闲」变「回放中」，进度条同步走
5. 任何异常点「⛔ 停止」：会先把增益降 0 再释放模式，不会把机器人留在僵住状态

### 4. 前置条件
- 网线接到 G1，本机 `192.168.123.222/24`（用 `tools\一键连接机器人.bat` 配）
- `ping 192.168.123.161` 通；不通时页面会直接提示「机器人不可达」，不会硬发指令
- 动作桥 `shiqian_v9/motion_bridge.py` 用 conda g1 的 Python 跑（要 numpy + DDS）；
  页面右上角「启动动作桥」会自动找解释器并托管（日志进「进程与日志」）
- 低层模式中途点「停止」或出错时，桥会先把增益降到 0、再把模式交还机器人，
  不会把机器人留在"僵住但通电"的状态

## 十六、策略跟踪模式（自稳定回放 · 实验）

### 为什么需要它
开环回放（arm_sdk / lowlevel）只是把关节角按时间轴硬发下去，机器人不会
"自己找平衡"。要像官方跳舞那样自己站稳，必须跑 RL 策略：50Hz 读一次状态、
重算一次目标。MuJoCo 实测对照（同一段动作、同一套 PD）：

| 回放方式 | 结果 |
|---|---|
| 开环 PD | **1.6 s 摔倒** |
| 策略跟踪 | **连续 20 s 不摔**，最低机身 0.732 m，腿部跟踪误差 0.17 rad |

### 开启步骤
1. 管道界面导出 **rl_sar 36 列 60Hz CSV**（「导出 rl_sar (60Hz)」），
   或直接用 `output/ours_60hz.csv`
2. 把 CSV 拖进「动作与剪影 → 导入动作文件」（.csv 支持）
3. `config.yaml` 里打开开关：
   ```yaml
   motion:
     allow_policy: true
     policy_root: D:/DATAWORK/G1        # policy_runner 所在工程
     policy_dir: ''                      # 留空=用 dance_102
   ```
4. 重启动作桥（进程与日志 → 重启模块 motion），回放模式选 **策略跟踪**
5. 首测必须：**吊架 + 有人扶 + 先跑 5 秒**

### 底层做了什么
- 释放内置运动模式 → 缓慢站到 default 姿态（2 s）
- 50Hz：读 `rt/lowstate`（关节角/角速度/IMU）→ 拼 154 维观测 → 策略出 29 动作
- 把 `default + action_scale×action` 作为 **位置目标** 下发，kp/kd 用策略自带那套
  （和真机 rl_sar 一样，由电机内部做 PD）
- 结束/异常：先把 kp 降 0、kd 保留，再 ReleaseMode，交还控制器

### 注意
- `.g1motion` 只有 29 关节，没有 root 轨迹，**不能**用于策略模式，请用 CSV
- 预训练策略是"某一段动作"训出来的，跟踪我们的动作会有偏差（0.17 rad ≈ 10°），
  但**不会摔**；想要动作更像，需要针对该动作重新训练策略（Isaac Lab）
- 这套链路目前只在 MuJoCo 验证过，**真机首测必须吊架**

### 2. 视觉桥（vision_bridge.py，127.0.0.1:5013）

```
机载 MJPEG (8081) → vision_bridge → OpenCV 检测 → 主控台 /api/vision/*
```

### 3. 相机稳定性：实测 5 分钟后 USB 掉链

2026-11-18 15:26–15:32 连续采样（每 20 秒抓 2 秒）：

```

... 稳定 15.5~16.0 fps ...
15:31:04  fps=15.5
15:31:29  ERR TimeoutError
15:32:17  ERR TimeoutError
```

同时 Jetson 内核：

```

usb 2-2.1: USB disconnect, device number 3

```

`error -71` 是 USB 协议层错误，电源循环后仍然枚举不了 —— **这是物理链路问题**（排线/接口/供电），
不是驱动或软件。软件侧能做的都做了：

- `g1cam.service`（systemd）开机自启、`Restart=always`；
