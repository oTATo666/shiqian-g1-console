# 为什么导出的动作不会"自己站稳"，以及怎么做到官方那样

## 一、结论先说

**PD 不是平衡控制器。** 我们导出的是 29 个关节角的时间序列，机器人用
`kp*(q_target - q) + kd*(0 - dq)` 去跟——这是一个**位置伺服环**，它只保证
"关节尽量转到指定角度"，完全不知道：

- 重心现在在哪、会不会出支撑面
- 脚该往哪落、要不要迈一步救回来
- 地面反作用力够不够

所以只要动作本身让重心离开脚掌范围，机器人就按物理规律倒——**调 PID 只能让它
倒得更硬或更软，不会让它不倒**。

官方跳舞之所以稳，是因为它不是回放关节角，而是跑一个**神经网络策略**：

```
参考动作(60Hz) ──┐
本体感觉(关节角/角速度/IMU) ──→ 策略(154维观测) ──→ 29关节目标位置(50Hz) ──→ PD
                     ↑                                              │
                     └──────── 每 5ms 闭环一次 ─────────────────────┘
```

策略是在 Isaac Gym 里用几千个并行机器人、加噪声加推力训练出来的，学会了
"偏了就修正"，这才是平衡的来源。它输出的仍然是关节目标，但**目标是每 5ms 根据
当前状态重新算的**，而我们的目标是 100ms 前就写死的。

## 二、我们手上其实已经有官方那套东西

`G1_DevKit/04_rl/rl_sar/policy/g1/whole_body_tracking/` 下：

| 文件 | 作用 |
|---|---|
| `dance_102/policy.pt` | 预训练全身跟踪策略（154 维观测，29 动作） |
| `dance_102/G1_Take_102.bvh_60hz.csv` | 参考动作，**36 列 60Hz——和我们 `rlsar_export` 完全同格式** |

| `gangnam_style/` | 同上，江南 style |

也就是说：**我们的导出格式天生就能当它的参考动作**，缺的只是一个"跑策略"的进程。

## 三、观测怎么拼（从 rl_sar 源码抄的，154 维）

```
motion_command            58  = 参考动作 29 关节位置 + 29 关节速度
motion_anchor_ori_b        6  = 机身重力方向在躯干系的投影 - 参考躯干朝向投影
ang_vel                    3
dof_pos                   29  = 当前关节角 - default_dof_pos
dof_vel                   29
actions                   29  = 上一帧策略输出
                        ────
                         154
```
`policy.pt` 是 TorchScript（zip 里是 `policy/data/*`），`torch.jit.load` 可直接加载。

## 四、落地路线（按风险从低到高）

### 阶段 0：本机先"体检"（已完成）
`pipeline/stability.py`：算重心与支撑多边形，把动作分成

| 判定 | 含义 | 处置 |
|---|---|---|
| `stable` | 重心始终在脚掌内 | 可直接开环回放 |
| `marginal` | 偶尔擦边 | 0.5x + 有人扶，或自动缩幅 |
| `dynamic` | 单脚/腾空占比高（步态类） | **开环必倒**，必须 RL 或锁腿 |
| `infeasible` | 全程着地但重心出界 | 自动缩幅，缩不下来就拦截 |

GUI 里"稳定性审查 / 自动可行化"两个按钮；导出和低层回放前都会自动拦。

### 阶段 1：MuJoCo 里验证策略（下一步，1~2 天）
1. `pip install torch`（CPU 版即可，仅推理）
2. 写 `pipeline/policy_runner.py`：加载 `policy.pt`，按上面 154 维拼观测，
   在 `g1_29dof_rev_1_0.xml` 里跑闭环（`mujoco` 已装好）
3. 喂我们导出的 CSV，看跟踪误差、会不会倒；调 action_scale / kp/kd

### 阶段 2：真机（需谨慎，建议吊架起）

2. 再在吊架下跑低层 + 策略
3. 最后去掉吊架，从 0.5x 速度和简单动作开始

## 五、做不到的动作怎么办（三条策略）

1. **能改就改**：`make_feasible()` 朝静止姿态收缩，找最大可行幅度（已实现）
2. **改不了就换通道**：`arm_sdk` 锁腿只做上半身；或导出 rl_sar 格式交给策略
3. **都不行就拦**：低层回放前直接拒绝，并说明原因（已实现）

## 六、关键数字（写代码时要用）

- 脚掌约 0.25 × 0.10 m，支撑面很小 → 重心偏差 3cm 就很危险
- 低层控制周期 2ms，策略 50Hz（每 4 个控制周期出一次动作）
- `dance_102` 的 rl_kp/rl_kd 是**训练时用的增益**，和我们默认的 60/1 完全不同，
  换成策略时必须同时换这套增益

### ✅ 突破：仿真里已经能自己站稳了

根因是三条叠加，最后一条最隐蔽：

1. `model.opt.timestep=0.002`，我按 5 ms 推进 → 策略时间轴快 2.5 倍
2. 默认姿态正确站高 ≈ **0.775 m**（0.74 穿地 1.7 cm）
3. **官方 MJCF 的 `dof_damping` / `dof_armature` 全是 0** —— 这是纯运动学模型，
   真机电机有阻尼。不加这两项，任何 PD 都会"软腿"倒下；
   补上 `damping=0.6 / armature=0.02` 之后立刻稳。

实测（MuJoCo，2 ms 控制 / 50 Hz 策略）：

| 场景 | 结果 |
|---|---|
| 官方舞蹈 + 策略 | **20 s 不摔**，最低机身 0.732 m |
| 官方舞蹈 + 开环 PD | **1.76 s 摔倒** |
| 我们的走路动作 + 策略 | **20 s 不摔**，最低 0.721 m，腿部跟踪误差 0.17 rad |
| 我们的走路动作 + 开环 PD | **1.6 s 摔倒** |

也就是说：**同一段动作，开环必倒，策略能站住**——这就是官方跳舞能自稳定的原因。

## 九、开环控制怎么落地（时间轴分段 + 安全段导出）

### 1. 时间轴分段
`stability.segment_report(q, fps, window=0.5)` 把整段切成 0.5 秒的小格，
逐格判三色：

| 颜色 | 判据 | 含义 |
|---|---|---|
| 🟢 safe | 双脚着地 且 margin ≥ 3 cm | 可开环回放 |
| 🟡 warn | 双脚着地 但 margin < 3 cm | 擦边，0.5x + 有人扶 |
| 🔴 risky | 腾空 >30% / 单脚 >30% / margin < 0 | 开环必倒 |

GUI「预览」页进度条下方就是这个色带，**点色带可以直接跳帧**。

### 2. 安全段导出
`safe_ranges(segs, min_sec=0.6)` 把连续绿格合并成区间，
「导出安全段」按段各存一个 `.g1motion`（文件名带起止时间）。

实测（bvh-recording 走路 18.1 s / 1807 帧）：

| 阶段 | 结果 |
|---|---|
| 原始 | 37 格中 **35 红**，无可导出段 |
| 锁腿改造后 | 35 绿 + 2 黄，切出 2 段（0–7.5 s、8.5–18.1 s）|
| 导出的段再审查 | **STABLE，margin +3.0 cm** |

### 3. 想全身开环，动作必须满足（硬指标）
1. 双脚始终着地（抬脚 ≤3 cm）
2. 重心距支撑边 ≥3 cm
3. 关节角速度 <1 rad/s
4. 段间停顿 0.3–0.5 s

做到这四条，`segment_report` 会整段绿，直接导出就能开环回放。

### 4. 分段自适应降速（只救"太快"的动作）
`stability.retime_by_speed(q, fps, target_vel=1.2, max_stretch=3, window=0.25)`
按 0.25 秒窗口算**峰值关节角速度**，超标的窗口单独拉慢（最多 3 倍），
其余窗口保持原速——比整段降速省时间，也不会把慢动作拖得更慢。

GUI「预览 → 稳定性审查 → 分段降速」。

实测（bvh-recording 走路）：

| 步骤 | 结果 |
|---|---|
| 原始 | 峰值 **7.40 rad/s**，18.1 s，判定 DYNAMIC |
| 分段降速 | 32 个窗口拉慢，18.1 s → **28.7 s**，峰值降到阈值内 |
| 再锁腿 | 判定 **STABLE**，边距 +3.1 cm，**58/58 格全绿** |

推荐顺序：先「分段降速」再「锁腿改造」——降速让过渡更柔和，
锁腿后的站姿切换不会被原来的高速帧撕开。
